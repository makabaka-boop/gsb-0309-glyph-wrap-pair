# Compose Glyph — 离线像素字形紧凑排版

排版区可设置每行最大像素宽度（8～128）。当下一字在当前行的最早无黑像素重叠位置放不进整幅字形外框时，排版应换到下一行；每行从 x=0 开始，行间保留一行空白。输入字串中的换行符表示强制换行，连续换行保留空行；换行符本身不需要字形，也不应在位置列表中出现。换行后碰撞只比较同一行的字形，来源颜色和位置序号仍对应原字串中的字形；单字外框比行宽大时应报告排版错误并撤销旧预览。位置列表、最小包围盒、画布尺寸、PNG 与位置 JSON 应反映相同的二维结果，包括空行占用的画布高度。

Vue 3 + TypeScript + Vite 的**纯离线**单页应用：在一个 glyph 页面上编辑 2～40 个
**同高黑白字形**（每个宽/高 1～32 像素），输入长度不超过 80 码点的字串，然后按
**黑像素实际形状**紧凑排版，输出每个字形位置、最小包围盒与按字形来源标色的合成图，
并可导出 PNG 与位置 JSON（二者来自同一次排版结果）。

## 为什么不能只按外框宽度、也不能只看相邻两字

- 像素字形有大量空白凹口，按外框宽度机械排版会在字间留下明显缝隙：
  后字的笔画可以伸进前字的空白凹口，黑像素不重叠即可。
- 但只检查相邻两字不够：第三字可能越过第二字，撞上**第一字**的伸出笔画。
  因此放置每个字时要与**所有已放字形**逐一做黑像素碰撞。

## 排版规则（精确语义）

1. 每行首字左边缘 `x = 0`；同一行内，之后每个字从 `前一字 x + 1` 开始枚举整数候选
   （保证左边缘**严格递增**），取**不与同一行任何已放字形的黑像素重合**
   且整幅字形外框不超过每行最大宽度的最小整数 `x`。
2. 在行宽内找不到这样的候选时（碰撞可能把所有可容纳位置都占掉）换到下一行，
   新行从 `x = 0` 重新开始。
3. **空白像素允许互相覆盖**，碰撞判定只看黑像素；换行后碰撞只比较同一行的字形。
4. 输入中的换行符（`\n`，CRLF/CR 先规范化为 `\n`）表示**强制换行**，
   连续换行保留空行；换行符本身不要字形、不占位置序号。
5. 全部字形同高；第 `r` 视觉行（从 0 起）的字形上边缘
   `y = r * (pageHeight + 1)`，行间保留一行空白。
6. 单字外框宽于行宽时无法靠换行容纳：报告 `glyph-too-wide` 排版错误并撤销旧预览。
7. 最终包围盒 = 所有已放黑像素的全局（二维）最小包围矩形；
   合成图没有任何黑像素（全空）时包围盒记为 **`EMPTY`**（JSON 中为字符串 `"EMPTY"`，
   内部为 `null`）。
8. 缺失字符、页面/位图非法时：**保留当前编辑内容，但撤销旧排版**（清空结果），
   并展示具体错误；修复后重新点击“排版”即可。

画布宽度 = 所有视觉行的最大外框宽度（至少 1），画布高度 =
`行数 * pageHeight + (行数 - 1)`——前导/连续/末尾换行产生的空行也占用高度。
位置列表、包围盒、PNG 与位置 JSON 均来自同一个二维 `Layout`。

### 碰撞算法

每个字形的每一行位图压成一个 32 位整数掩码（位 c = 第 c 列黑像素）。
两字在水平偏移 `dx` 下碰撞，当存在某一行满足

```
maskA[r] & (maskB[r] << dx) !== 0
```

注意 JS 移位位数按 `dx & 31` 回绕，因此 `dx >= 32` 必须显式判定为“无重叠列”
（字形宽 ≤ 32）。

## 测试策略（`src/lib/*.test.ts`、`src/test/`）

- `src/test/reference.ts` 提供**朴素逐像素参考实现**（全局黑像素占用格 Set，
  无任何位运算优化）与确定性 PRNG 用例生成器（稀疏/实心/竖条/凹口/长臂形态，
  含约 12% 全空字形）。
- 快速位掩码实现与朴素实现对拍：
  - 200 组小尺寸 + 24 组全尺寸上限（40 字形 / 32×32 / 80 字串）+ 全实心、全空极端；
  - 160 组多行对拍（注入 `\n`/`\r\n`/`\r`、随机行宽，覆盖自动换行、强制换行、连续空行）；
  - 每组独立穷举校验：行首 x=0、行内 x 严格递增、全局二维占用格无任何重复
    （覆盖隔字碰撞、跨行不碰撞）、每个被跳过的候选偏移都确实与同行某个已放字碰撞
    （**逐偏移穷举极小性**）、换行决策重模拟一致、行数/画布高度（含空行）、
    bbox 独立逐像素重算一致。
- `masksCollide` 对随机 32 宽位图穷举 `dx = 0..40`（覆盖 31/32/33 移位回绕边界），
  与逐像素判定对拍。
- 手工用例覆盖：**长伸出笔画**（第三字撞第一字）、**全空字形**（EMPTY、空白互相覆盖）、
  **重复字符**（每次出现独立放置、来源颜色不同）。
- 错误处理：空串、超 80 码点（代理对按码点计数）、缺失字符、非法位图、
  单字外框宽于行宽（`glyph-too-wide`）；仅含换行的字串是合法空行排版。
- 手工多行用例：行宽 8 的 `ABA`（碰撞占掉可容纳位置而折行）、宽于行宽的单字报错、
  手动换行/连续空行、CRLF 规范化、跨行相同 x 的黑像素不碰撞。
- 导出测试：PNG 编码 → 解码后与栅格数据逐像素一致；
  位置 JSON 的每个位置/颜色都能在解码 PNG 中逐像素对上，证明二者同源。
- Vue 组件 jsdom 冒烟测试：点击排版、缺字撤销旧排版但保留编辑、恢复后重新排版。

## 导出同源保证

一次“排版”只产生一个 `ExportSnapshot { layout, raster }`：

- 位置 JSON 由 `snapshot.layout` 序列化；
- PNG 由 `snapshot.raster`（同一个 `layout` 栅格化）编码。

任何编辑动作（改字符、改像素、缩放、增删字形）都会立即丢弃快照，
从源头杜绝 PNG 与 JSON 来自两套位置。
